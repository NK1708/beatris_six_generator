# Установка Bearridge AI Generator

## Системные требования

- Node.js 20.18–22.x (рекомендуется версия из `.nvmrc`);
- npm 10 или новее;
- Git;
- около 2 ГБ свободного места для зависимостей, проектов и изображений.

API-ключи не нужны для локального mock-режима. Ключи Gemini/OpenAI задаются только через `.env`, если вы сознательно используете соответствующий provider.

## Первый запуск

Во всех системах команды выполняются из корня клонированного репозитория:

```bash
npm ci
npm run setup
npm run dev
```

Откройте `http://127.0.0.1:5173`. Backend работает на `http://127.0.0.1:4317`.

`npm run setup` безопасно запускается повторно. Команда собирает внутренние пакеты, генерирует Prisma Client, собирает приложение, создаёт отсутствующий каталог проектов и только глобальный реестр `app.sqlite`. Существующие project SQLite не открываются и не мигрируются.

Относительный `PROJECTS_ROOT` всегда разрешается от каталога `apps/api`, независимо от текущего рабочего каталога. Поэтому значение по умолчанию `./projects` означает `apps/api/projects` на Windows, macOS и Linux. Для внешнего каталога можно указать абсолютный путь.

### Windows

Установите Node.js 20 LTS с официального установщика или через nvm-windows, затем используйте PowerShell:

```powershell
npm ci
npm run setup
npm run dev
```

### macOS

При использовании nvm:

```bash
nvm install
nvm use
npm ci
npm run setup
npm run dev
```

### Linux

Установите Node.js через nvm или пакетный менеджер дистрибутива. Проверьте, что версия соответствует `.nvmrc`, затем выполните обычные команды первого запуска.

## Последующие запуски

```bash
npm run dev
```

Перед dev-серверами автоматически собираются `@bearridge/shared` и `@bearridge/core`. После обновления зависимостей или Prisma schema повторите:

```bash
npm ci
npm run setup
```

## Диагностика

```bash
npm run doctor
```

Doctor ничего не меняет и проверяет Node/npm, зависимости, сборки внутренних пакетов, Prisma Client, API/web build и доступность каталога проектов. Для каждой ошибки выводится команда исправления.

Типовые случаи:

- `Failed to resolve @bearridge/shared` или отсутствует `core/dist`: запустите `npm run setup`.
- отсутствует `@babel/core/lib/index.js`: удалите только локальный `node_modules`, затем выполните `npm ci`; не добавляйте Babel вручную.
- Prisma Client не найден: `npm run prisma:generate` или `npm run setup`.
- `project.json not found`: выбрана не корневая папка проекта.
- `PROJECT_ID_MISMATCH`: `project.json` и `project.sqlite` принадлежат разным проектам; восстановите папку из одной резервной копии.
- каталог проекта недоступен: проверьте путь и права, затем откройте текущую папку через поле «Открыть проект».

Для npm не требуется `npm approve-scripts`. Эта команда относится к другим package manager. Не отключайте install scripts Prisma/esbuild при обычном `npm ci`.

## Перенос проекта

Проект переносится всей папкой, включая:

- `project.sqlite`;
- `project.json`;
- `characters`, `locations`, `style`, `frames`, `generations`, `references`, `exports` и остальные вложенные каталоги.

Порядок переноса:

1. Остановите Bearridge.
2. Скопируйте всю папку проекта на новый компьютер.
3. Запустите Bearridge.
4. Введите новый путь в поле «Открыть проект».

Приложение сверяет ID из `project.json` и `project.sqlite`, регистрирует текущий путь и использует его вместо старого Windows/macOS/Linux пути. Проекты внутри `PROJECTS_ROOT` могут быть автоматически найдены после перемещения по ID. Если проект находится снаружи, выберите папку вручную — приложение не сканирует произвольные диски.

Одинаковые названия допустимы: проекты связываются по ID, а не по имени. Если найдено несколько папок с одним ID, автоматическое открытие блокируется до ручного выбора.

## Резервное копирование

Остановите приложение и скопируйте всю папку проекта. Не копируйте отдельно только SQLite: изображения и generation provenance хранятся рядом с ним.

Глобальный `app.sqlite` — только реестр путей. Для восстановления production-проекта он не нужен: проект можно открыть заново по его папке.

## Дополнительные команды

```bash
npm run doctor
npm run typecheck
npm test
npm run build
```

`npm run prisma:migrate` и `npm run prisma:push` не нужны для обычной установки и не должны запускаться на пользовательском проекте без отдельной задачи по миграции.
